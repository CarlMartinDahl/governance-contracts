## 4. Exact-Match and Fail-Closed Posture

- the reference must be a string
- the reference must equal one exact allowed `CASE_ID`
- case folding, trimming, coercion, aliases, prefixes, suffixes, and wildcard
  matching are not authorized
- an unknown or malformed token must fail closed in any future separately
  authorized contract
- the exact future validator error code, path, and precedence remain governed
  by `RTRE-P07` and `RTRE-P08`

No runtime allowlist, registry, lookup, resolver, dispatcher, or currentness
check is created by this documentation boundary.

## 5. Prohibited Reference Forms and Meanings

The corpus reference is not:

- an object or array
- a URL, URI, filesystem path, repository path, commit, branch, or PR reference
- a source locator, evidence locator, package locator, or private-material locator
- a database key, tenant key, user identity, provider identity, model identity,
  run identity, or execution identity
- a request to look up, load, fetch, resolve, persist, or execute anything
- proof that the corpus item exists at runtime, is current, was executed, was
  produced by a model, or is true

The reference creates no source-truth, identity-truth, authorship-truth,
chain-of-custody, currentness, execution, adherence, or result-truth conclusion.

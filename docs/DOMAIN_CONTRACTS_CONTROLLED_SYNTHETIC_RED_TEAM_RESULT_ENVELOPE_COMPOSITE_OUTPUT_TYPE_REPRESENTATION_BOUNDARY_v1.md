This boundary resolves only `RTRE-P04`, the composite output-type
representation prerequisite for a possible future machine-readable controlled
synthetic red-team result envelope.

output type without selecting, dropping, reordering, or independently
interpreting either component. It does not choose a future top-level field
name, field placement, wrapper shape, field order, schema, validator, parser,
provider execution, or runtime behavior.

## 4. Exact-Match and Fail-Closed Posture

- the represented output type must equal the complete canonical string
- neither component may be selected as a substitute for the composite value
- component order must not be reversed
- whitespace, delimiter, case, spelling, and underscore placement must not be
  normalized or inferred
- splitting, joining, sorting, deduplication, aliasing, coercion, array
  conversion, and set conversion are not authorized
- an unknown, partial, reordered, malformed, or normalized value must fail
  closed in any future separately authorized contract
- the exact future validator error code, path, and precedence remain governed
  by `RTRE-P07` and `RTRE-P08`

No parser, tokenizer, component dispatcher, approval flow, or execution path is
created by this documentation boundary.

## 5. Component Meaning Boundary

`NO_OVERCLAIM_WARNING` and `OWNER_DECISION_REQUEST` remain output artifact
labels inside one canonical output-type value. Their presence does not mean:

- a warning has been generated or delivered
- an Owner decision has been requested, received, or completed
- the Owner gate has been passed
- review, approval, readiness, release, product, client-facing use, or external
  use has been authorized
- any automatic next action may start

The composite value is not a score, severity, truth claim, legal conclusion,
evidentiary conclusion, technical sign-off, compliance result, or execution
instruction.

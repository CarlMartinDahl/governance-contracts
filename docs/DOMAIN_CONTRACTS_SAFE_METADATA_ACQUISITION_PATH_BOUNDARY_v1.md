# Safe Metadata Acquisition Path Boundary

Boundary name: `SAFE_METADATA_ACQUISITION_PATH_BOUNDARY`

Status: `DOCS_ONLY`

Purpose: freeze a safe metadata acquisition path boundary for possible later actual text-primary chunk metadata work without raw text, source inspection, private facts, source locators, inference, or conclusions.

## Scope

This boundary defines safe metadata acquisition paths only.

It does not acquire metadata.

It does not create a real source review matrix.

It does not create an evidence/proof matrix.

It does not authorize actual private source processing.

It does not authorize raw text review.

It does not authorize PDF/image/metadata/source package inspection.

It does not authorize a real large-source private run.

It does not authorize external-use readiness.

It does not select a product candidate.

Product candidate remains none.

It does not infer per-chunk metadata.

It does not bypass `ACTUAL_CHUNK_METADATA_AVAILABILITY_GAP_BOUNDARY`.

Human/professional review remains the release gate.

Data-handling unknowns remain unresolved and not bypassed.

## Acquisition Path Classifications

### Manual Human/Professional Review Attestation

Classification: `DOCS_ONLY_CONCEPT_ONLY`

Manual human/professional review attestation is allowed only as a future path if separately specified.

It must not include raw text, source locators, private facts, exact dates, filenames, page references, URLs/tokens, PDF/image/metadata content, or sensitive event details.

It must be separately reviewed before use.

### Separately Generated No-Raw Metadata Manifest

Classification: `HYPOTHETICAL_UNTIL_CONTRACTED`

A separately generated no-raw metadata manifest may become allowed only after a separate contract or boundary.

It must use no-raw, no-source-locator, no-private-fact metadata only.

It must not become proof.

### Deterministic Preprocessor Output

Classification: `HYPOTHETICAL_UNTIL_CONTRACTED`

Deterministic preprocessor output may become allowed only after a separate contract or boundary and test evidence.

It must be deterministic, no-raw, auditable, and validation-without-conclusion.

It must not inspect or emit raw content in this slice.

### Reviewed Chunk Ledger

Classification: `HYPOTHETICAL_UNTIL_CONTRACTED`

A reviewed chunk ledger may become allowed only after a separate ledger boundary and proof test.

It must be repo-relative or no-raw reference-only.

It must not include source locators, filenames, exact dates, raw excerpts, or private facts.

### Other Documented No-Raw Mechanism

Classification: `ABSENT_NOT_AVAILABLE`

Other documented no-raw mechanisms are not usable until separately documented, reviewed, and tested.
